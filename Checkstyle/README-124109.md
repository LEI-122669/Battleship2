# Checkstyle – Convenção de nomes de constantes (Ficha 3, Tarefa 2B)

## Regra escolhida

**`ConstantName`**: as constantes (campos `static final`) devem estar em maiúsculas, com palavras separadas por `_` (por exemplo `MAX_SHIPS`), segundo as convenções da Oracle e da Google para Java.

Expressão regular usada: `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$`

## Ficheiros

| Ficheiro | Função |
|---|---|
| `checkstyle-124109.xml` | Configuração do Checkstyle, só com a regra `ConstantName` e severidade `error` |
| `.github/workflows/checkstyle-124109.yaml` | Workflow do GitHub Actions (quality gate) com a action `dbelyaev/action-checkstyle@v3`, que corre em pull request e falha quando há violações (`fail_level: error`) |

## Bloquear o merge

A regra de proteção do ramo `main`, que exige que os checks passem antes do merge de um pull request, já tinha sido configurada no repositório por um colega do grupo. Por isso não foi criada uma nova regra para este workflow.

## O que o Checkstyle não consegue verificar

O Checkstyle só verifica a forma do nome através de uma expressão regular, não o seu significado: aceita `MAX_SHIPS`, mas também aceitaria `X` ou `AAA_BBB`, que não dizem nada sobre o valor que guardam. Também não consegue saber se um nome está em português ou em inglês de forma coerente com o resto do código, nem se o campo devia de facto ser uma constante.
